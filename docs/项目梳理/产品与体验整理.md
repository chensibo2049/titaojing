# 产品与体验整理

> 内部工作文档｜2026-11-17 北京时间。事实取自本地 `a3121f8`；生产版本另见[总览](项目总览.md)。以下“建议”均未实施，暖白方向未经用户最终批准。本轮没有删除功能。

## 1. 产品边界与核心路径

**定位**：给师范生、教师及表达练习者的一面练习镜子。首要场景是个人试讲回看；领导汇报、路演与大会表达是可探索场景，不等于各场景评价规则均已成熟。不要与独立产品 kaijiang.chensibo.cn 混同。

**建议主线：讲两分钟 → 回看一个具体时刻 → 找到下一次改的一处。**

| 步骤 | 用户应完成的事 | 当前依据／缺口 |
|---|---|---|
| 了解 | 知道适合谁、能看什么、数据去哪 | 官网已有价值、流程、语文观察表与隐私 FAQ，`landing/index.html:145-250`；入口与 README 仍有版本措辞分裂 |
| 准备 | 选短练习、确认镜头、选择听写与录像 | `index.html:135-193`；应明确不听写也能做视觉练习，不能将听写失败描述成整次失败 |
| 练习 | 专注讲一段，而非追逐所有实时指标 | `index.html:258-294`；模拟课堂默认不开，属于规则模拟而非真人反馈（`:172-178`） |
| 回看 | 点具体事件／一句转写回到时刻 | `index.html:297-332`、`src/main.js:1894`；需真人真机验证时间对齐，不以预设 demo 验收替代 |
| 改一处 | 从有证据的发现选一个下次行动 | `src/analyze.js:586-615` 有诊断文字，但观测、推断与建议仍需分层 |
| 再练 | 在相近条件下复练并自查 | 本机历史与趋势可用；跨设备同步不存在，改善效果尚无本轮验证 |

## 2. 页面职责：官网讲价值，工作台做操作，报告给证据

| 页面 | 保留的首要任务 | 应折叠／避免 |
|---|---|---|
| 官网 `/landing/` | 谁适合、练完得到什么、三步开始、真实与 demo 边界、隐私限制 | 堆叠技术参数和未实现愿景；把版本史放到更新记录 |
| 工作台入口 `#/` | 一个主按钮“开始两分钟练习”，次按钮“先看预设演示” | 与官网重复长篇介绍；多个同权重 CTA |
| 准备／站位 | 权限、画幅、输入来源、听写状态、是否保存录像 | 高级灵敏度和调试指标默认折叠，保留入口 |
| 实时练习 | 稳定画面、时长、明确结束按钮、温和提示 | 密集解释、排名、未经验证的分数；不阻断用户开口 |
| 回放／报告 | 证据时刻、下一步、缺失原因 | 将未转写写成“口头禅零次”、将面向镜头写成真实眼神交流 |
| 历史／设置 | 本机数据管理、比较条件、模型与缓存管理 | “登录即可同步”之类未实现承诺 |

## 3. 官网信息结构与可用文案框架（建议稿）

既有首页已写“先讲出来，再看清楚”和“看一个时刻，而不是一个分数”（`landing/index.html:148-178`），不应为了重整再推倒重写。

1. **首屏**：OpenPodium · 开讲；“先讲出来，再看清楚。”副标题：“给试讲与表达练习留下一段可回看的线索，从一个具体时刻开始，找到下一次能改的一处。”按钮：“开始练习”；次入口：“看预设演示”。
2. **一次练习能得到什么**：带时刻的动作与面向线索；有听写时的转写和口头禅标记；一个可自行选择的改进动作。不可写“精准读懂情绪／自动客观打分”。
3. **三步使用**：准备镜头 → 讲两分钟 → 回看一处。注明首次视觉资源加载与可选听写包下载。
4. **真实示例位置**：只放获得同意的实际练习；没有案例前显示“预设交互演示”，绝不伪造转写或前后对比。
5. **适用与不适用**：个人练习优先；不是考试评分、心理诊断、精确眼动或教学质量认证。
6. **隐私与限制**：视觉在本机；本机听写与浏览器听写分别说明；本机历史不跨域迁移；无业务后台与团队同步。
7. **结尾**：“下一次开口，从这一段开始。”再次开始练习，技术资料作为次链接。

以上是项目产品文案，不使用个人／公司身份背书，不代表新皮肤获批。

## 4. 报告结构建议

按“来源 → 观测 → 解释／建议 → 缺失”呈现，而不是按功能数量排列：

- **顶部来源条**：真人实时／本地视频／预设样本；版本、时长、采集条件、是否有视觉／声音／录像。demo 提前结束仍展示完整预设样本，不能说是已观看片段的识别结果（`origin/main:docs/演示结束补丁发布-20261116.md:7-8`）。
- **观测层**：时间戳、原话或可回看画面、算法事件及覆盖情况。“估计面向镜头”不升级为“关注学生”。
- **解释层**：场景与规则版本、适用条件、推断依据；语文试讲解释属于场景模块，不是通用人格评价。
- **下一次只改一处**：允许用户自己选择；动作必须具体、能复练，避免“提升感染力”等抽象结论。
- **缺失层**：未授权、无模型、听写网络失败、识别覆盖不足、导入视频无音轨分析分别列原因。缺失显示“无法判断”，不是零分或零次。`src/observe.js:587-628` 已有部分缺失门控，应统一各导出渠道。
- **导出页脚**：输入来源、版本、限制、数据位置；报告不是专家认证。打印实现见 `src/report.js:8-69`，是否与回放语义完全一致尚待逐项验证。

## 5. 功能取舍建议（不直接下线）

| 功能 | 建议 | 原因／验收方向 |
|---|---|---|
| 短练习、站位、回放、历史、证据跳转 | 核心保留 | 每一步服务主线；真人完成一次不靠人工补数据 |
| 转写／口头禅 | 可选保留 | 模型下载、隐私与失败降级明确；不因缺语音产生错误夸奖 |
| 语文观察表 | 场景入口保留 | 用于试讲解释，不塞入 Core 的通用定义 |
| 视频导入 | 次入口保留 | 当前仅视觉、不转写、不进历史；必须先告知（`src/main.js:464-504`） |
| 3D 预设演示 | 次入口保留 | 仅 demo 懒加载和演示回放，失败可降 2D；不是视觉模型识别 |
| 模拟课堂／路演、长课堂模式 | 折叠到场景／高级 | 有实现不等于首轮用户都需要；规则回复不能称智能学生或真实观众反馈 |
| 调试、轨迹、灵敏度、研究选项 | 高级入口保留 | 不干扰新用户；研究另行知情同意 |
| 激活、云账号等预留表单 | 建议评估隐藏或标“未开通” | 当前无安全授权或云账号服务；移除需用户确认，不能本轮直接删除 |
| SDK／插件市场、团队后台 | 仅规划 | 无可交付实现，不作为官网可点击功能 |

## 6. UI 当前风格与候选新方向

**当前源码风格**：纸色 `#f3eee4`、浅纸色 `#faf7f0`、朱砂 `#a33b28`、青绿 `#2f6f6a`，标题宋体／正文无衬线，偏纸墨教学讲义。依据 `landing/styles.css:1-34`、`assets/app.css:1-37`。这是静态 CSS 判断，本轮未打开浏览器，不冒充现场视觉审查。

**候选方向：暖白练习室**。保留亲和与练习感，暖白底、松绿主操作、减少装饰，工具优先；这是建议而非批准。另可保持“纸墨教学工具”做轻度减法，避免新旧主题叠加。

由 Designer 后续提交“入口／准备／回放”三页同一套样稿，比较信息层级、可读性、触控区域、手机首屏与空态，而不是只给色卡。由用户选方向后 Developer 实施，不本轮代替设计或编码。

## 7. 首要问题顺序

1. 版本与文档事实不一致；先消除错误承诺，再加功能。
2. 没有新的真实案例贯穿“开始—回看—选一处—复练”，演示完整不能替代用户闭环。
3. 观测与评价边界仍混用，Core 中还包含教学解释与肯定／建议句式。
4. 听写来源、下载与缺失状态要在进入练习前说清，而非到报告才解释。
5. 当前视觉体系与暖白建议要明确取舍，避免多代理反复换皮。
