# 路线图：版本、平台与开源模式

> 本文是项目规划，不是承诺。日期以月为粒度，随测试反馈调整。欢迎在 Issue 里讨论。

**现在是 v1.6.0（2026-11-15）。** 已经落地：课堂 10–20 分钟、半身 / 全身构图、空格开讲与结束（电脑放在讲台上不必走回去）、回放转写与水词标亮、手部关键点与写板回视、**本机听写**（v1.2 起，约 90 MB，声音不出设备）、语文试讲观察表（v1.4）、一键演示与模拟课堂里的 3D 人物（v1.5–v1.6）、介绍页与 GitHub Pages 网页版。桌面 / App 安装包、真机测试与阈值校准仍是下一阶段（见第 6 节）。每一版具体改了什么见 [`CHANGELOG.md`](../CHANGELOG.md)。转写方案见 [`ASR.md`](ASR.md)，课堂摆放见 [`CLASSROOM.md`](CLASSROOM.md)。


## 1. 总原则：一套核心，多端外壳

体态镜的核心是**一个纯前端网页应用**（`src/` + `index.html`）：摄像头、MediaPipe 关键点、规则引擎、回放、历史全在浏览器里完成，没有后端。所以各平台不重写，而是"外壳 + 同一份网页"：

```
                 ┌──────────── 同一份 dist/（网页 + 模型）────────────┐
  网页 / PWA ────┤ 浏览器直接打开（现在）                              │
  Windows / Mac ─┤ Tauri 外壳（系统 WebView2 / WKWebView）             │
  安卓 / iOS ────┤ Capacitor 外壳（系统 WebView）                      │
                 └─────────────────────────────────────────────────────┘
  微信小程序 ──── 不能直接复用（见第 2.4 节），后期单独做"轻量版"
```

各端唯一需要分别处理的是：**摄像头 / 麦克风权限**、**语音识别**（系统 WebView 里没有 Web Speech）、**签名与上架**。

## 2. 各平台方案

### 2.1 网页 / PWA（现在，v1.x，已上线）

- 部署到 https 静态主机即可，见 [`DEPLOY.md`](DEPLOY.md)。可"添加到主屏幕"、离线使用。
- 优点：零安装、更新即时、所有平台都能打开，是推广（扫码即用）和测试的主力。
- 限制：手机必须 https；微信内置浏览器里镜头不可靠。口头禅可以用浏览器在线听写（在中国大陆常连不上），也可以下载本机听写（v1.2 起）。

### 2.2 Windows / macOS 桌面版：推荐 Tauri（v1.8 体验版）

骨架在 [`apps/desktop/`](../apps/desktop/)（未构建）。

| | Tauri 2 | Electron |
|---|---|---|
| 安装包体积 | 外壳约几 MB（+ 我们 31 MB 资源） | 外壳约 80–120 MB（自带 Chromium）|
| 内存占用 | 低（用系统 WebView） | 高 |
| 渲染内核 | Windows: WebView2（Chromium），macOS: WKWebView（Safari 内核） | 各平台一致的 Chromium |
| 后端语言 | Rust（我们几乎不需要写） | Node.js |
| Web Speech 语音识别 | 系统 WebView 均**不可用** | Electron 里同样**不可用**（需要谷歌密钥）|

两者在语音上处境相同，都要靠第 3 节的本地语音识别；Tauri 更小更省资源，适合学生机房和旧笔记本，所以推荐 Tauri。

需要注意：

- **macOS 摄像头权限**：`Info.plist` 里写 `NSCameraUsageDescription`、`NSMicrophoneUsageDescription`（骨架里已写）；启用 Hardened Runtime 时还需要 entitlements `com.apple.security.device.camera`、`com.apple.security.device.audio-input`（骨架里已写）。首次打开系统会弹窗；被拒后要到「系统设置 → 隐私与安全性」里打开。
- **macOS 签名与公证**：要让用户双击就能打开，需要加入 Apple Developer Program（年费 99 美元；用公司名义注册需要邓白氏编码 D-U-N-S），用 Developer ID 证书签名，再用 `notarytool` 提交 Apple 公证。没有签名的话，用户需要右键 → 打开，或在设置里放行。
- **Windows 签名**：没有代码签名证书时 SmartScreen 会提示"未知发布者"。可先发未签名测试版，正式版购买 OV/EV 代码签名证书（国内 CA 代理商可买，几百到几千元/年）。
- **WebView2**：Windows 10/11 基本都自带；安装包可选内嵌引导程序。
- **待验证**：自定义协议（`tauri://` / `http://tauri.localhost`）下 Service Worker、IndexedDB、`getUserMedia` 的行为，第一次真机构建时重点测。

### 2.3 安卓 / iOS App：Capacitor（安卓 v1.8 体验版，iOS v2.0）

骨架在 [`apps/mobile/`](../apps/mobile/)（未构建）。Capacitor 把 `dist/` 放进原生 App 的 WebView 里，原生能力用插件补。

- **安卓**：`AndroidManifest.xml` 需要 `CAMERA`、`RECORD_AUDIO` 权限；Capacitor 的 WebView 会把网页的 `getUserMedia` 请求转成系统权限弹窗。`androidScheme: "https"` 让页面成为安全上下文。
- **iOS**：WKWebView 从 iOS 14.3 起支持 `getUserMedia`；`Info.plist` 写摄像头 / 麦克风用途说明。
- **语音**：WebView 里没有 Web Speech。可选 `@capacitor-community/speech-recognition` 插件（iOS 用系统 SFSpeechRecognizer；安卓用系统 SpeechRecognizer——**国内很多安卓手机没有谷歌服务，可能用不了**），所以安卓更推荐直接上第 3 节的本地识别（sherpa-onnx 原生版）或接入国内语音 SDK。
- **上架**：国内安卓应用商店普遍要求**软件著作权登记证书**、隐私政策、App 备案（工信部 2023 年起要求 App 备案）；iOS 在中国大陆上架同样需要 ICP 备案号；iOS 需要 Apple 开发者账号。早期可以先发安卓 APK 直装包给测试同学，iOS 用 TestFlight。
- 也可以不做 App：PWA "添加到主屏幕"已经能满足大部分场景，App 的主要价值是**应用商店曝光**、更稳定的权限和后台录制、以及本地语音识别。

### 2.4 微信小程序：后期单独做"轻量版"（v2.x 调研）

坦白说，小程序**不能直接跑现在这套代码**：

- 小程序没有浏览器 DOM，MediaPipe 网页版依赖的 `document`、WebGL canvas、`fetch` 加载模型等都不可用；小程序虽然支持 WebAssembly（`WXWebAssembly`），但要求 wasm 文件打进代码包，而代码包有体积上限（主包 2 MB，分包合计有限额），我们的 WASM + 模型约 21 MB，放不下。

两条路：

1. **web-view 套壳**：小程序里用 `<web-view>` 打开我们的 https 网站。需要企业主体的小程序（沉思波公司可以）并在后台配置**业务域名**。但 web-view 里摄像头和麦克风基本不可用（尤其 iOS），所以只适合"一键演示、历史、报告查看"，**不能试讲**。
2. **原生重写**：用小程序的 `<camera>` 组件取帧 + 微信 **VisionKit**（`wx.createVKSession`）的人体关键点 / 人脸检测能力，语音用"微信同声传译"插件。好消息是我们的规则引擎 `src/analyze.js` 是纯 JS，只要把 VisionKit 的关键点映射成 BlazePose 的 33 点编号，规则、回放、诊断逻辑大部分能复用。工作量相当于一个新前端，关键点精度和机型兼容性需要实测。

建议：v1.x–v2.0 先把网页和 App 做扎实，小程序第一步只做 **web-view 入口 + 扫码跳转浏览器**（用于传播），等数据和规则稳定后再评估原生重写。

## 3. 跨平台的关键技术项：本地语音识别

桌面、App、小程序都拿不到浏览器的 Web Speech，而且在线识别有隐私和国内可用性问题。所以**本地中文语音识别**（sherpa-onnx 等）是多端发布的前置条件。网页版的本机听写已在 v1.2 落地（见 [`ASR.md`](ASR.md)），桌面 / App 外壳可以直接复用同一份；外壳里的下载、缓存和麦克风权限仍要在第一次真机构建时验证。训练相关见 [`TRAINING.md`](TRAINING.md) 第 D 阶段。

## 4. 版本与发布

### 版本号：语义化版本 `主.次.修订`

- **修订号**（1.0.**1**）：修 bug、改文案，不改数据格式；
- **次版本**（1.**1**.0）：新功能，向后兼容（历史记录、轨迹格式能继续读）；
- **主版本**（**2**.0.0）：不兼容的变化（例如历史记录格式迁移、规则大改导致分数不可比）。
- 所有平台共用同一个版本号（核心版本），外壳自己的修复用构建号区分。每个构建还有唯一构建号（`版本-内容哈希`），反馈时自动带上。

### 发布渠道

| 渠道 | 标签 | 给谁 | 网址示例 |
|---|---|---|---|
| **体验版**（beta） | `v1.7.0-beta.1` | 测试同学、合作老师 | `beta.你的域名` |
| **正式版**（stable） | `v1.7.0` | 所有人 | `你的域名` |

流程：功能分支 → PR（CI 构建 + 冒烟测试通过、至少 1 人审阅）→ 合入 `main` → 打 `-beta` 标签部署体验版 → 测试一轮无阻断问题 → 打正式标签部署正式版。推送 `v*` 标签时 GitHub Actions 会自动构建测试包并挂到 Release。

## 5. 开源模式与版本划分（适合学生创业的 open-core）

代码以 **Apache-2.0** 开源。建议：

| | 开源社区版（免费） | 学校 / 机构版（付费服务） |
|---|---|---|
| 形态 | 本仓库全部代码；官方网站、PWA、桌面版、App | 社区版 + 服务 |
| 功能 | 个人试讲、回放、诊断、历史、对比、导出——**不阉割** | 班级 / 课程管理；教师端批量查看学生试讲报告和趋势；按学科 / 比赛定制的评分维度和规则；数据看板 |
| 部署 | 自己部署或用官网 | 私有化部署到学校内网（数据不出校）、对接学校统一认证 |
| 支持 | 社区 Issue | 安装培训、试讲工作坊、师范生技能大赛 / 教师资格证面试赛前训练营、优先支持 |

几点建议：

- **社区版不要设人为限制**。开源后任何人都能改掉 `config.js` 里的试用开关，限制只会伤害口碑。现在 `config.js` 的"试用版最多 5 次"可以只留给官网的托管服务用，或干脆把开源版默认改为不限次数（**这个需要你来决定，代码目前未改**）。
- 收入来自**服务和机构功能**（需要后端、账号、运维的部分），这些可以放在单独的私有仓库，和开源核心通过清晰的接口对接（`src/license.js` 就是预留的接口）。
- **商标单独保护**：Apache-2.0 不授予商标权（许可证第 6 条）。建议尽早注册"沉思波""体态镜"商标，在 README 里声明：别人可以自由使用代码，但不能用这两个名字和标识发布自己的版本。
- **学术合作**：与学院合作建立数据集和评测（`TRAINING.md`），形成论文 / 教改项目 / 大创项目，是学校宣传师范专业和公司背书的最好结合点。对外宣传时注意：这是学生发起的开源项目，**涉及学校名义和标识的宣传需要先经学校同意**。
- 申请软件著作权登记（上架和投标都会用到）。
