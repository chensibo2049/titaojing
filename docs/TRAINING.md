# "训练"路线图：怎样把体态镜做到最好

先说实话：**体态镜现在还没有经过任何训练。** 它由两部分组成——

1. **预训练的关键点模型**：Google MediaPipe 的 Pose Landmarker（身体 33 点）和 Face Landmarker（面部 478 点），原样使用，在浏览器里本地运行；
2. **手写的规则**（`src/analyze.js`）：例如"视线 pitch > 0.20 持续 1.15 秒 → 视线落下"、"2.4 秒内髋部水平摆幅 > 0.035 且来回穿越 → 晃动"。这些阈值是开发时凭经验和合成演示调出来的，**没有用真实师范生数据校准过**，也没有和专家判断对比过。

所以现在说"准确率多少"是没有依据的。要做到"最好"，需要的不是更大的模型，而是**一套经得起检验的数据和评测**。

## 1. 为什么不去重新训练姿态模型

- MediaPipe 的关键点模型是在大规模数据上训练的，"人在哪、肩膀在哪"这件事它已经做得很好；我们自己几百条试讲视频重新训练只会更差。
- 我们真正缺的是**上层判断**："这算不算晃动""这算不算没回视"——这是教学法问题，只有师范专业老师能定义和标注。
- 关键点（而不是视频）作为训练输入，数据量小、隐私风险低、能在浏览器里实时跑。

结论：**底层用现成模型，上层用我们自己的数据和标注做校准和小模型。**

## 2. 分阶段路线

| 阶段 | 做什么 | 产出 | 需要的人 |
|---|---|---|---|
| **A. 数据集** | 征集师范生志愿者试讲，导出轨迹（关键点 + 听写事件），由学科教学法老师按统一说明标注 | 带同意书、去标识的数据集 v0（目标 ≥ 100 人次、≥ 300 段） | 项目组、2–3 名专业老师、伦理审查 |
| **B. 阈值校准** | 用标注数据网格搜索每条规则的阈值和持续时间，按说话人交叉验证 | `calibration.json` → 改 `src/analyze.js` 默认值；公布各类事件的 P/R/F1 | 1 名开发 |
| **C. 时序小模型** | 在关键点序列上训练 1D-CNN / GRU 等小模型（几千到几万参数），导出 ONNX / TF.js 在浏览器跑；只在比规则明显更好时替换 | 体积 < 1 MB 的模型 + 对比报告 | 1–2 名开发 |
| **D. 本地中文语音识别** | 用 sherpa-onnx（WASM）等在浏览器本地识别，去掉对 Chrome/Edge 在线语音的依赖；口头禅用关键词检测（KWS）或专门的小分类器 | 断网也能统计口头禅；隐私说明可以改为"声音也不出本机" | 1 名开发 |
| **E. 评测体系** | 固定测试集、评分员一致性、公开评测报告，每个版本跑一遍 | `docs/EVAL.md` + 每版报告 | 全员 |

### A. 数据集怎么建

- **采集**：志愿者在 App 里用 `?debug=1&trace=1`（将来会做成正式的"参与研究"开关，**默认关闭、需主动勾选**）完成 2–3 分钟试讲，导出轨迹 JSON。只有专家标注时需要看视频：视频在本机或学院内网的受控电脑上播放，标注完成后删除，不进入数据集。
- **内容**：覆盖不同学科（语文、数学、英语……）、不同学段（小学 / 初中 / 高中）、不同设备（手机前置、电脑摄像头）、不同场地（教室讲台、宿舍、微格教室）、不同体型和着装。
- **标注**：按 [`TRACE_FORMAT.md`](TRACE_FORMAT.md) 的 `titaojing-labels` 格式，每段至少 2 名评分员独立标注：
  - 事件时间段：`sway`（晃动）、`slouch`（含胸）、`gaze_down`（视线落下）、`board_no_lookback`（写板未回视）；口头禅以转写文本标注。
  - 整体评分（1–5 分）：教态、视线交流、板书、语言表达、总体。维度参照**中小学教师资格考试面试**评分要素（如仪表仪态、言语表达、教学实施等）和**师范生教学技能大赛**（如江苏省师范生教学基本功大赛）的试讲 / 板书评分细则，具体条目请以学院和当年官方细则为准，由专业老师定稿。
  - 先写《标注说明》，每类事件配正例 / 反例 / 边界例子；先试标 20–30 段，算一致性，不达标就改说明再标。

### B. 阈值校准

`training/calibrate.py` 已实现基线：对"视线落下""晃动"两条规则网格搜索 `(阈值, 最短持续时间)`，以事件级 F1 为目标，按**说话人**划分训练 / 验证（同一个人的数据不能同时出现在两边），并和 App 当前默认值对比。其余规则照此扩展。

### C. 时序小模型

`training/train_gru.py` 是一个最小 GRU 基线：输入 2 秒（30 帧 @15fps）关键点窗口，特征为相对肩部归一化的上半身 13 点坐标与置信度、视线 yaw/pitch、板书标记、髋部位置和速度（共 45 维），输出 4 类事件的多标签概率，可导出 ONNX。模型 7 千多个参数，浏览器里用 onnxruntime-web 或 TF.js 运行毫无压力。

替换原则：**只有在固定测试集上明显优于校准后的规则、且各设备 / 各人群上没有明显变差时才上线**；规则版始终保留作对照和兜底。

### D. 本地中文语音识别

- 现状：口头禅依赖浏览器的 Web Speech API，Chrome / Edge 会把声音发到厂商的在线服务，Safari 依赖 Siri 听写，Firefox 和多数国产浏览器、微信不支持。
- 方向：[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0，支持 WebAssembly、流式中文模型和关键词检测）；Whisper 系列（whisper.cpp WASM）中文小模型精度一般、大模型太重，不建议在手机浏览器里用；[FunASR](https://github.com/modelscope/FunASR)（Paraformer 等中文模型）适合将来做学校版的私有化服务。
- 难点：很多 ASR 模型会把"嗯、啊、呃"当噪声**过滤掉**，而这恰恰是我们要数的。所以要么选保留语气词的模型，要么做专门的关键词检测 / 语气词分类器，需要单独采集和标注音频（伦理要求更高）。
- 体积：流式中文模型量化后通常几十 MB，需要按需下载并缓存，不能放进首屏。

### E. 评测协议

1. **固定测试集**：数据集按说话人划出 20% 作为测试集，冻结，不参与任何调参。
2. **评分员一致性**：事件类用帧级 Cohen's kappa 和事件级 F1，整体评分用二次加权 kappa（`training/agreement.py`）。一般认为 kappa ≥ 0.6 才算可用；**模型的指标不应宣传超过评分员之间的一致性**。
3. **模型指标**：每类事件的精确率 / 召回率 / F1（事件级，±0.5 秒容差），整体评分的 kappa 和平均绝对误差；分设备、分性别、分学科报告，检查有没有某一组明显变差。
4. **每个版本**发布前跑一遍，结果写入 CHANGELOG 和评测报告。对外宣传只引用测试集上的数字，并注明样本量。

## 3. 数据伦理（必须先于采集完成）

- **伦理审查**：数据采集方案（目的、流程、同意书、存储、销毁）先提交学院的学术 / 伦理委员会审查，获批后再开始。
- **知情同意**：书面或电子同意书，讲清楚收集什么（关键点、听写事件、评分）、不收集什么（默认不保留视频和音频）、用途、保存期限、谁能访问、能否用于公开数据集或论文；**自愿参与、可随时撤回**，撤回后删除其数据；参与与否不影响课程成绩。
- **不涉及未成年人**：只招募年满 18 周岁的师范生；不在有中小学生的真实课堂录制（实习课堂里学生出镜不可接受）。
- **个人信息保护**：依照《个人信息保护法》，关键点和声音数据可能属于敏感个人信息，需要单独同意、最小必要收集。数据用随机编号，同意书和编号对照表分开保存。
- **存储**：数据存放在境内、访问受控的位置（学院服务器或加密网盘），传输加密，只有项目组成员可访问，定期审计；明确保存期限，到期销毁。
- **App 内默认不收集**：正式的"参与研究"功能必须是 **opt-in**（默认关闭、主动勾选、可随时关闭），上传前展示将要提交的内容，并提供删除通道。
- **公开发布**：只发布经过参与者明确同意的去标识轨迹和标注；不发布视频、音频、原始听写文字。

## 4. 训练脚手架怎么用

```bash
cd training
pip install -r requirements.txt     # 国内加 -i https://pypi.tuna.tsinghua.edu.cn/simple
bash run_synthetic_demo.sh          # ⚠ 用合成数据跑通全流程
```

| 文件 | 作用 |
|---|---|
| `titaojing_train/schema.py` | 轨迹 / 标注格式常量与校验 |
| `titaojing_train/loader.py` | 读取轨迹和标注，重采样到 15 fps，提取 45 维特征，切滑动窗口 |
| `titaojing_train/metrics.py` | 事件级 P/R/F1、Cohen's kappa、加权 kappa |
| `titaojing_train/synth.py` | **合成数据**生成器（明确标记 `synthetic: true`） |
| `validate.py` | 校验文件格式 |
| `agreement.py` | 两位评分员的一致性 |
| `calibrate.py` | 规则阈值校准基线（只需 numpy） |
| `train_gru.py` | GRU 时序基线（需 PyTorch，可导出 ONNX） |
| `examples/` | 一条很短的合成轨迹和标注，用来看格式 |

> ⚠ `data/synthetic/` 里的数据是脚本按设定规则生成的，模型在上面的高分**只说明代码能跑通**，不代表任何真实效果，请不要引用。

真实数据：把轨迹放到 `training/data/real/`（已在 `.gitignore` 中排除，**永远不要提交到仓库**），标注放同一目录，运行 `python calibrate.py data/real`、`python train_gru.py data/real`。
